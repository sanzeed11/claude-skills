17.1 · The design system

Every room of the site, labelled.

The component library, its two stylesheets and the kit page that documents every state. Edit components.css directly; re-render with render-kit.sh.

Two stylesheets. brand.css (15_SOURCE_FILES/Project_Files/brand-kit) carries tokens, @font-face, the type classes and the base components; components.css (07_WEBSITE_DIGITAL_ASSETS/UI_Components) adds everything the site needs — nav, footer, hero, buttons, links, cards, forms, modal, dropdown, breadcrumbs, sections, pull quote, CTA, gallery with filters and pager, video, editorial, loading, empty, 404, toast, tags, table, pagination, tabs, accordion, motion.

Dark is the default; html[data-theme="light"] switches the whole page to the label. .bg-dusk forces dark tokens on a section inside a light page.

The kit. ui-kit.html is one long page of labelled specimens — 26 sections, each with a counter, a description and dashed spec boxes labelled by state. tokens-reference.html prints every token with a live specimen. Full-page renders at 1440 / 1280 / 834 / 390 and the light theme sit in renders/.

Accessibility. Gold focus rings (2 px + 3 px offset) on every interactive element; skip link; labels on every control; aria-current / pressed / selected / expanded; 44 px tap targets; colour pairs from Colour_Reference.md; prefers-reduced-motion honoured globally.

17.5 · Light theme and tokens

The label, one attribute away.

Components use the semantic tokens (--bg, --fg, --accent …), never palette names, so the theme switches without a second stylesheet.

17.6 · Responsive views

Four widths, one system.

Fluid type (clamp) from 1440 to 390; the gallery steps 3 → 2 → 1 columns; the nav folds below 900 px; container queries drive the card grid.
